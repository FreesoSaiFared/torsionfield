Product completeness

What the specification settles, what this website implements and what still requires engineering closure.

Coherent core contracts

The stable core is now clear: durable operation identity, self-describing capability actors, observable postconditions, replaceable adapters, local ownership, bounded delegation, evidence and recovery. The architecture no longer depends on one daemon language, one browser actuator or one provider.

Verified executable today

The new ScriptCat Node VM semantic harness is verified on the Windows host: three modules built, 7/7 tests passed, restart deduplication and userscript rollback passed, and an authenticated loopback call passed. Local Repomix remains a live capability actor. Neither result is the production extension or Rust node.

Current exact boundary

The Debian 13 executor is NEEDS_REPAIR: Podman is present but its Linux machine/socket is unavailable and the image build exits 125. Live browser effects remain virtual in the new harness.

Not yet implementation-complete

A final architecture is not a compiled product. The following artifacts remain mandatory before the software itself can be called complete:

  • Exact ScriptCat upstream revision and file-by-file patch dossier.
  • Generated JSON Schemas and TypeScript/Rust protocol types.
  • Browser-specific manifest permissions and migration behavior.
  • UI wireframes, keyboard model and state machines.
  • Provider fixtures and automated live acceptance accounts.
  • Installers, signing, updates, rollback and incident procedures.
  • Threat model, capability-policy tests and requirement-to-test manifest.

Website status

The public product site, documentation host, status/manifest APIs and D1-backed alpha-interest registration are deployed. Registration is not yet production P2P enrollment and does not issue node credentials.
